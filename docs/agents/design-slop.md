# 設計 slop：為什麼 `design/vibe-slop/` 的十頁是反例

修改本專案任何視覺樣式前先讀這份。`design/vibe-slop/` 裡的十個頁面是刻意做出來的 **slop**：
一眼就能認出「這是 AI 隨手生成的」的設計。它們保留下來當對照組，不是候選方案。

## slop 的判準

一個檢查就夠：**把桃園、天氣、十三區全部拿掉，這個頁面還成立嗎？**
成立，就是 slop。它的外觀來自「某個流行模板」，不是來自這個主題。

slop 有三個共同症狀，十頁全部中：

1. **視覺語言與主題無關。** 紫色漸層、霓虹、像素風，套在天氣、記帳、待辦清單上都一樣。
2. **裝飾取代資訊。** 圓角、陰影、玻璃、發光、徽章蓋在每個區塊上，層級被抹平，讀者分不出「現在 31°」和「氣壓 1006」哪個重要。
3. **只有一種尺寸的想法。** 整頁用同一個圓角、同一種卡片、同一個陰影，等於沒有做決定。

## `index.html` 的定位

`index.html` 現在是選定的方向：`design/redesign/07-xiangsu.html` 接上真實資料後的正式版（2026-09-04 定案）。
它保留 10-pixel 的調色盤與框格排版，拿掉的是讀者要解碼的東西：遊戲語彙、當作數值的狀態條、掃描線、漸層、英文標題。
改樣式時延續它的視覺語言：NES 固定調色盤、黑底白框、一格對應一個真實單位、數字一律真實單位。
資料層（Open-Meteo 抓取、十三區座標、快取、氣象署授權碼）沿用舊版，不要動。

其餘六個提案在 `design/redesign/`，每個都附「這跟桃園或天氣有什麼關係」的理由，可當日後改版的參考。

## 唯一的硬約束

- **資料是即時的。** 所有數字來自 Open-Meteo（可選 CWA）。任何寫死數字的區塊都是示範，必須標示。

其他一切都開放：視覺方向、配色、深淺主題、字體、版面、十三區怎麼呈現、甚至介面語言，都由提案決定。
使用者之前提過的偏好（互動地圖、海軍藍深色主題、zh-TW 文案）只是參考，不是門檻，可以為了更好的方向放掉。

自由的代價是每個選擇都要答得出「這跟桃園或天氣有什麼關係」。答不出來的選擇就是上面說的 slop。

## 十個反例：症狀 → 改法

| 檔案 | 流派 | 為什麼是 slop | 在本專案該怎麼做 |
|---|---|---|---|
| 01-glass | 紫藍漸層玻璃擬態 | `#667eea→#764ba2` 是 AI 生成的預設色；模糊玻璃卡讓文字對比失守；emoji 當圖示無法換色與縮放。 | 顏色要答得出主題理由；圖示一律 inline SVG；區塊邊界靠留白或細線，不靠模糊。 |
| 02-saas | Tailwind SaaS 落地頁 | 對天氣頁而言，定價、見證、Logo 牆是**不存在的內容**；漸層標題字與 indigo-600 按鈕是框架預設，不是決定。 | 頁面只放讀者要的：現在、接下來、哪一區。沒有內容的區塊直接刪，不用版面填。 |
| 03-neon | 賽博龐克霓虹 | 三層 text-shadow 發光降低可讀性；全部大寫英文與桃園使用者無關；掃描線是純裝飾。 | 動態只留一處；語言與字體為目標讀者設定，不為「駭客感」設定。 |
| 04-bento | Apple 便當格 | 每格一個數字、同一圓角、同一陰影，層級被抹平；28px 圓角與 160px 細體是抄來的，不是算出來的。 | 大數字只給「現在氣溫」一個；其他細節用清單，不用格子。 |
| 05-brutal | Neubrutalism | 黃底黑框硬陰影是純風格宣言，跟氣象資料沒有關係；跑馬燈把資訊變成噪音。 | 版面安靜，讓數字與地圖說話。 |
| 06-terminal | 駭客終端機 | ASCII 表格在手機上無法排版；綠字黑底對長時間閱讀不友善；「hacker」是給開發者的自我投射，不是給桃園市民。 | 表格用真正的 HTML `table`，隨寬度重排；配色以長時間閱讀的可讀性為先。 |
| 07-admin | 管理後台模板 | 側欄導航、KPI 卡、「較昨日 ↑2.1°」、甜甜圈圖是企業儀表板的**形狀**，天氣頁沒有這些流程；十三區用資料表加狀態膠囊，是把地圖降級成試算表。 | 十三區的呈現要保留它們的空間關係，不降級成試算表；比較昨天的數字只在真有意義時才出現。 |
| 08-kawaii | 粉彩可愛風 | 吉祥物、漂浮愛心、emoji 是氣氛，不是資訊；粉彩對比度普遍不足。 | 溫度感靠色階，不靠裝飾。 |
| 09-nimbus | Vercel／Linear 純黑開發者頁 | 純黑 `#000`、13px 小字、「Powered by AI ✦」徽章、「Trusted by」灰色字標，全是開發者工具的視覺借用；英文標題對本地讀者是隔閡。 | 深色底要有主題理由，不是預設純黑；正文字級 16px 起；標題與內文同一語言。 |
| 10-pixel | 8-bit RPG 像素 | HP／MP 條把濕度、紫外線包成遊戲數值，讀者得先解碼；Press Start 2P 中文不支援，必須混第二套字體。 | 數值用它本來的單位與尺度（%、hPa、UV 指數）直接呈現。 |

## 跨十頁重複出現、以後一律不要的手法

每一條後面都是替代做法，改樣式時直接照做：

- **漸層當背景** → 單一表面色，深度靠細線與留白。
- **每個區塊都是圓角卡片** → 只有需要被「拿起來」的東西才是卡片（例如浮動的工具提示）；其餘用標題與間距分區。
- **陰影疊在陰影上** → 一頁最多一種陰影，用在最多一種元件上。
- **emoji 當天氣圖示** → 單一筆觸風格的 inline SVG，可換色、可縮放。
- **「AI」「Powered by」徽章** → 頁面不需要宣稱自己是什麼；資料來源寫在頁尾。
- **假內容撐版面**（定價、見證、Logo 牆、「10,000+ 使用者」） → 沒有的東西不放。
- **英文標語配中文內文** → 標題與內文同一語言。
- **Inter 當「安全」字體** → 字體是決定，不是預設：選了要能說出理由，而且中文字體要與西文字體認真配對。
- **全頁動畫**（漂浮、閃爍、掃描線、跑馬燈） → 動態只留一處，且尊重 `prefers-reduced-motion`。
- **一個數字一個大格子** → 大字只給最重要的一個數字。

## 交付前的檢查

重設計或改樣式的工作，做到以下五項全部成立才算完成：

1. 拿掉「桃園」與天氣資料後頁面**不再成立**（視覺語言綁定主題）。
2. 頁面上的每個顏色都答得出主題理由，不是從模板或框架預設繼承來的。
3. 只有一個視覺亮點，其他區塊安靜。
4. 手機寬度（390px）沒有橫向捲動，表格自行重排。
5. 頁面提供的每個主題都讀得清楚。
